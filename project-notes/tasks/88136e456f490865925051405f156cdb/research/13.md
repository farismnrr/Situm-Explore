## Two-line summary

The web application currently uses PostgreSQL for identity, registration verification, and workspace data; Drizzle’s config and migration history are PostgreSQL-specific.  
The README documents `npm run dev`, but login needs a configured database and registration also needs the email-verification service; neither requires Situm credentials.

## 1. PostgreSQL usage and SQLite move

**Observed:** The PostgreSQL client and schema are in [server/db/client.ts](/workspace/server/db/client.ts) and [server/db/schema.ts](/workspace/server/db/schema.ts). The schema imports `pg-core` and defines six tables with PostgreSQL UUIDs, timestamps, checks, foreign keys, and unique constraints. [drizzle.config.ts](/workspace/drizzle.config.ts) selects the `postgresql` dialect and uses `DATABASE_URL` plus `DATABASE_SCHEMA`. The same variables appear in [.env.example](/workspace/.env.example), [nuxt.config.ts](/workspace/nuxt.config.ts), and [scripts/materialize-staging-env.sh](/workspace/scripts/materialize-staging-env.sh).

Database operations use the shared client throughout `server/api/` and `server/utils/`; current PostgreSQL-specific telemetry attributes appear in [server/api/me.get.ts](/workspace/server/api/me.get.ts). The migration history is `drizzle/0000` through `drizzle/0011`, with SQL and snapshots under `drizzle/` and `drizzle/meta/`.

**Porting concerns:** The configured PostgreSQL schema/search-path model (`DATABASE_SCHEMA`), UUID column defaults, and migrations need SQLite equivalents. Migration `drizzle/0010_move_app_tables_to_configured_schema.sql` uses PostgreSQL PL/pgSQL, `current_setting`, `RAISE EXCEPTION`, `to_regclass`, and schema moves. Registration also handles PostgreSQL’s unique-violation code `23505` in [server/api/auth/register.post.ts](/workspace/server/api/auth/register.post.ts). These are the clearest PostgreSQL-only portability points. The product also uses Drizzle `returning()` and SQL expressions; their target-dialect support should be checked during conversion.

**Dependency note:** `package.json` currently depends on `pg` and `@types/pg`, not `better-sqlite3`. The assigned SQLite approach notes using npm with `--ignore-scripts`; no install or package change was performed in this research.

## 3. Starting the web app and auth flow

The README setup is `npm install`, copy `.env.example` to `.env`, then `npm run dev` ([README.md](/workspace/README.md)). The package script runs `nuxt dev` ([package.json](/workspace/package.json)); no explicit dev port is set there, so Nuxt’s default applies. Staging maps host port `3005` to container port `3000` in [deploy/staging.compose.yml](/workspace/deploy/staging.compose.yml).

The app’s configured database client requires `DATABASE_URL` and a valid `DATABASE_SCHEMA`; the Drizzle migration command is `npm run db:migrate`. The supplied env example contains PostgreSQL placeholders, so a working database and migrations are needed for auth endpoints. Sessions are configured through `NUXT_SESSION_PASSWORD` in [nuxt.config.ts](/workspace/nuxt.config.ts).

Registration at `/register` sends a six-digit email verification code, then submits the code, email, and password; the code expires after five minutes ([app/pages/register.vue](/workspace/app/pages/register.vue), [server/api/auth/send-verification-code.post.ts](/workspace/server/api/auth/send-verification-code.post.ts), [server/api/auth/register.post.ts](/workspace/server/api/auth/register.post.ts)). Email delivery loads SMTP settings through Sensio Env ([server/integrations/sensio-env/mail.ts](/workspace/server/integrations/sensio-env/mail.ts)). Login at `/login` checks the stored email/password and creates a session ([app/pages/login.vue](/workspace/app/pages/login.vue), [server/api/auth/login.post.ts](/workspace/server/api/auth/login.post.ts)).

**Situm credentials:** Neither registration nor login checks for Situm credentials. Situm credentials are configured later per workspace in the app, as reflected in [app/pages/app/workspaces.vue](/workspace/app/pages/app/workspaces.vue) and [ARCHITECTURE.md](/workspace/ARCHITECTURE.md).
